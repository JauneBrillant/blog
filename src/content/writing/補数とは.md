# 補数とは

## イントロダクション
補数とはなんでしょうか？
おそらくほとんどの人は資格試験でなんとなく用語を目にしたことがあり、
理解しないまま、まあ直近の必要性も感じないし、と流してしまっていることでしょう。

私も最近まではその一人で、しかしコンピュータについて理解を深めようとするたびに、
こいつに対面することになり、ようやく重い腰を上げることとなりました。

結論から言うと、
**補数を使うと、引き算を、引き算をせずに足し算だけでできる**ようになります。

「なぜ補数を使うと、足し算だけで、引き算ができる様になるのか」
「どうして引き算を、足し算だけでやりたいのか」

など、疑問がつきませんね。楽しくなってきました！

---
## ざっくり

１０進数の世界で考えると

３という数字の「１０の補数」: ７ 
３という数字の「９の補数」  : ６

２進数では

０という数字の「１の補数」 : １
１という数字の「１の補数」 : ０

になります。

「補数」とはcomplement（補うもの）の訳語で、
「ある数に足すと、キリのいい数になる相手」をさします。

---
## 補数の種類
１０進数では、「１０の補数」と「９の補数」があります。
２進数では、「２の補数」と「１の補数」があります。
１６進数では、「１６の補数」と「１５の補数」があります。

つまり基数bに対して、「bの補数」と「b-1の補数」が存在することになります。

なぜこの２種類なのか、きっと理由があるはずです。

---
## 補数の性質 (９の補数、１の補数）
１０進数（つまり基数１０）で「２７の９の補数」を考えてみます。
ここで注意しておきたいのは、
「２７の９の補数」とは、２７を９にする相方の数を探すのではなく、
足し合わせた時に、各桁すべてが９になるような数のことをさします。

２７ + ７２ = ９９ より、 
「２７の９の補数」は「７２」になります。

おなじように、２進数（つまり基数２）で「０１０１」の１の補数を考えます。
足し合わせた時に各桁が１になるような補う数を考えるのでしたね。

０１０１ + １０１０ = １１１１
より、「０１０１の１の補数」は「１０１０」になります。

なるほど、基数bに対して、b-1の補数を使うと
１０進数だと、「９９」や「９９９９」などが
２進数だと、「１１１１」や「１１１１１」などがつくれるようになりました。

どうやら、基数bに対して、b-1の補数を使うと、
**あと１足すと桁上がりするような数**を作ることができそうですね。

---
## 補数の性質（１０の補数、２の補数）
こんどは、１０進数（つまり基数１０）で「２７の１０の補数」を考えてみます。
これも「２７を１０にする相方」ではありません。
足し合わせた時に、**ちょうど桁が１つ上がる数**（１００ のように、上の桁が
１で残りが全部０になる数）になるような数のことをさします。

２７ + ７３ = １００ より、
「２７の１０の補数」は「７３」になります。

おなじように、２進数（つまり基数２）で「０１０１」の２の補数を考えます。
足し合わせた時に、ちょうど桁が１つ上がる数になるような補う数でしたね。

０１０１ + １０１１ = １００００
より、「０１０１の２の補数」は「１０１１」になります。

なるほど、基数 b に対して、b の補数を使うと
１０進数だと、「１００」や「１００００」などが
２進数だと、「１００００」や「１００００００」などが
つくれるようになりました。

どうやら、基数 b に対して、b の補数を使うと、
**そのまま桁上がりした数**を作ることができそうですね。

---
## ２つの補数の関係性

２７の  ９の補数   ＝ ７２      →  ２７ + ７２ = ９９     （あと１で桁上がり）
２７の１０の補数   ＝ ７３      →  ２７ + ７３ = １００   （すでに桁上がり）

０１０１の１の補数 ＝ １０１０  →  和は １１１１          （あと１で桁上がり）
０１０１の２の補数 ＝ １０１１  →  和は １００００        （すでに桁上がり）

つまり

１０の補数　＝　９の補数 + １
２　の補数　＝　１の補数 + １ 

---
## 補数を使った足し算だけの引き算

いよいよ本題です。
まず、そもそもなぜ引き算を避けたいのかを確認しておきましょう。

### なぜ引き算がやっかいなのか

引き算には「**借り**」があります。

```
      ５２
    −　２７
    ------
```

一の位で ２ から ７ は引けないので、十の位から借りてきます。
この「借りる」という操作は、**隣の桁の状態に依存します**。
上の桁が ０ だったらさらにその上から借りる…と、連鎖することもあります。

ハードウェアで作ると、この借りの連鎖のために回路が複雑になります。
**足し算の回路だけで引き算もこなせたら、部品が減って嬉しい**わけです。

### １０の補数を使う方法

先ほど求めた「２７の１０の補数 ＝ ７３」を使って、５２ − ２７ を計算してみます。
引く代わりに、**足します**。

```
５２ ＋ ７３ ＝ １２５
```

３桁になってしまいました。ここで、あふれた **１００ を捨てます**。

```
→ ２５
```

答えは ２５。たしかに ５２ − ２７ ＝ ２５ です。
**引き算を一度も使っていません。**

なぜこれで合うのでしょうか。式を分解すると見えてきます。

```
５２ ＋ ７３
  ＝ ５２ ＋ （１００ − ２７）      ← ７３ の正体
  ＝ ５２ − ２７ ＋ １００
    ^^^^^^^^^^^ 欲しい答え
```

余計についてきた ＋１００ が、桁あふれで**勝手に消えてくれる**のです。
だから「あふれを捨てる」だけで正しい答えになります。

### ９の補数を使う方法

こんどは「２７の９の補数 ＝ ７２」で同じことをやってみます。

```
５２ ＋ ７２ ＝ １２４
```

あふれた １００ を捨てると ２４。……１足りません。
そこで、**捨てた代わりに １ を足します**。

```
２４ ＋ １ ＝ ２５
```

これで正解です。この操作を「**キャリーの折り返し**（end-around carry）」と呼びます。

なぜ１足すのか。これも式で分かります。

```
５２ ＋ ７２
  ＝ ５２ ＋ （９９ − ２７）          ← ７２ の正体
  ＝ ５２ ＋ （１００ − １ − ２７）    ← ９９ ＝ １００ − １ と分解
  ＝ ５２ − ２７ ＋ １００ − １
    ^^^^^^^^^^^ 欲しい答え
```

余計なものが２つ出てきました。

- 余計な ＋１００ → 桁あふれで勝手に消える
- 余計な −１ → 消えないので、自分で ＋１ して打ち消す

折り返しの ＋１ は思いつきの工夫ではなく、
９の補数を使った時点で**数学的に必然の補正**だったわけです。

### ２進数でも同じことが起きる

４bit で ５ − ３ を計算してみます。

```
３ ＝ ００１１
```

まず２の補数（＝ １００００ − ００１１ ＝ １１０１）を使うと、

```
０１０１ ＋ １１０１ ＝ １００１０
→ あふれた １００００ を捨てる → ００１０ ＝ ２
```

つぎに１の補数（＝ 全ビット反転 ＝ １１００）を使うと、

```
０１０１ ＋ １１００ ＝ １０００１
→ あふれた １００００ を捨てる → ０００１
→ ＋１ して折り返す　　　　　 → ００１０ ＝ ２
```

どちらも ５ − ３ ＝ ２ になりました。

### どちらを使うべきか

まとめると、こういうトレードオフになっています。

| | 補数を作るコスト | 引き算に使うときのコスト |
|---|---|---|
| b−1 の補数（９の補数、１の補数） | **安い**（各桁を独立に計算できる。２進数なら全ビット反転するだけ） | 折り返しの ＋１ が必要 |
| b の補数（１０の補数、２の補数） | b−1 の補数 ＋ １ が必要 | **安い**（あふれを捨てるだけ） |

「＋１ のコストを、補数を作るときに払うか、使うときに払うか」の違いです。

現代の CPU が採用しているのは **２の補数** です。
足し算・引き算は１秒間に何億回も実行されるので、
「使うときが安い」方が有利だからです。

いっぽう **１の補数** は、２進数では「全ビット反転」というきわめて安い操作で
作れるという長所があり、
インターネットのチェックサム計算などで今も現役で使われています。

## まとめ

補数というのは「引き算を、引き算をせずに足し算だけでやる」ために生まれた概念です。

最初に立てた２つの問いに答えると、

**「どうして引き算を、足し算だけでやりたいのか」**

引き算には「借り」があり、隣の桁に依存するため回路が複雑になるからです。
足し算の回路を使い回せれば、ハードウェアがぐっと単純になります。

**「なぜ補数を使うと、足し算だけで引き算ができるのか」**

補数は「引きたい数を、キリのいい数から引いたもの」です。
それを足すと、答えに余計なキリのいい数（１００ や １００００）がくっついてきますが、
その余計な分は**桁あふれで勝手に消えてくれます**。
結果として、引き算の答えだけが手元に残るのです。

そして「基数 b に対して b の補数と b−1 の補数の２種類がある」のは、
補正用の ＋１ を**先に払っておくか、後で払うか**という選択肢が２つあるから、
という話でした。
